# Octet state machines

Octet Measure and the Pi remote coordinate several independent workflows. This map groups code that makes different decisions based on a previous event, an in-flight operation, a durable record, or a timeout. It includes mixed workflows whose existing stage names cover only part of their lifecycle. The Pi entries describe the checkout. For live evidence, use the [web deployment workflow](agent-workflows/web-deployment.md) and [audio deployment gates](agent-workflows/audio-deployment.md).

The measurement handoff exposes a phase at the point where the microphone changes owners. The job manager decides when the slot is available, and the UI and API report that decision. Playback source, mute, DSP readiness and audio ownership remain independent inputs to the Pi's existing guards.

Progressive audio moves from URL resolution through prebuffering to response streaming. Failure before headers reports an error. ## Measurement job contract

The job manager owns the lifecycle. The same phase drives the Record page and the API. `state` describes work such as `monitoring`, `recording` or `analyzing`, while `phase` describes occupancy of the audio slot.

| Phase | Meaning |
|---|---|
| `idle` | No measurement session holds the slot. Auto Tune can still own audio independently. |
| `running` | A session holds the slot and may still be starting. Starting a measurement can request that an active meter release it. |
| `stopping` | The session has received cancellation and still holds the slot. If the meter takes longer than ten seconds to release it, the replacement request returns HTTP 409 and can be retried after idle. |

`GET /api/job` exposes `phase` alongside the existing `running`, `kind`, `state`, and result fields. The event stream sends `status` at start and on cancellation and carries `phase` on job `state` and `idle` events. The cancellation endpoint acknowledges the request. Idle confirms that the measurement session has exited.
